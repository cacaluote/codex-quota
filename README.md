# Codex Quota

Codex Quota 是 Windows 桌面上的 Codex 额度悬浮窗。它显示剩余额度、重置时间，以及本机 Codex 会话的 Token 用量。单击悬浮球可展开详情。

## 安装与启动

需要 Windows 10/11，以及已安装并登录的官方 Codex Desktop（Windows MSIX 安装包）或 Codex CLI。仅安装 Desktop 时，无须额外安装 CLI，也无须将 `codex` 加入 PATH；Desktop 关闭后仍可刷新额度。本机有 Codex 会话日志时，才能统计本机 Token 用量。

目前可从源码构建。准备 Rust stable 和 Windows MSVC 构建工具后，在项目目录运行：

~~~powershell
cargo build --release
~~~

生成的程序是 `target\release\codex-quota.exe`。运行后，悬浮球和系统托盘图标会出现。

## 日常使用

| 操作 | 效果 |
| --- | --- |
| 单击悬浮球 | 展开或收起额度面板 |
| 拖动悬浮球 | 在显示器工作区内移动，支持跨屏拖动；松开后会靠向屏幕边缘 |
| 右键单击托盘图标 | 打开操作与设置菜单 |
| 立即刷新 | 更新额度，并尝试更新模型价格 |
| 面板截图 | 将完整面板复制到剪贴板，也可在资源管理器中粘贴为 PNG 文件 |

托盘菜单可以切换刷新间隔（1、2、5、10、30 分钟）、Token 显示单位（万/亿或 K/M/B）和颜色风格。**设置**子菜单包含始终置顶、开机启动、面板常驻、重置倒计时和缓存命中率等开关。

**跟随 Codex** 默认关闭。开启后，只在 Codex Windows 应用或 CLI 运行时显示悬浮球；此时不能手动显示或隐藏悬浮球。

## 读懂面板

悬浮球通常显示短期额度的剩余百分比。任何一个有效额度窗口耗尽时显示 `0`；没有可用的最新额度时显示 `--`。低于 50% 会变为警告色，低于 20% 会变为紧张色。展开面板可分别查看各额度窗口。

| 面板内容 | 含义 |
| --- | --- |
| 5h、周或月额度 | 各窗口的剩余百分比和重置时间；倒计时可在设置中关闭 |
| 今日使用、本周／本月使用 | 本机在对应时段内的套餐内 Token 用量，以及 API 牌价等价金额 |
| 使用量后的百分比 | 输入 Token 的缓存命中率，例如 `1.2亿 · 98.1%`；可在设置中关闭 |
| 今日超额、本周／本月超额 | 触顶后的本机 Token 用量和账户 credits 实扣折算金额；没有超额时隐藏 |
| 本周／本月估值 | 按当前用量与额度进度推算的本期满额 Token 数及 API 等价金额，仅供参考 |
| 更新时间 | 最近一份额度快照的时间；过期时会提示“已过期” |

“本周／本月”跟随账号的长期额度窗口。缓存命中率只计算套餐内输入 Token，不包含输出或超额用量；没有可计算的输入时不显示百分比。

## 数据来源与限制

额度和重置时间来自本地 Codex 会话记录；需要更新时，程序会临时启动 Codex app-server 读取账户额度。查询优先使用 Desktop 随附后端；Desktop 未安装、安装信息查询失败或后端文件缺失时，回退到独立 CLI 的固定安装目录和 PATH。选定后端后的启动、认证或查询错误会直接报告，不会再切换另一份后端。本机没有新活动时，读数可能停留在上次快照，面板中的更新时间可帮助判断。快照过期或读取失败时，额度可能显示 `--`；`0` 表示已确认耗尽。

刷新间隔用于常规额度更新。窗口到达重置时间时会立即尝试刷新，面板对应的额度行显示“更新中”，取得新窗口后恢复百分比和重置时间。服务端暂未更新窗口或读取失败时，在首次请求后额外重试三次，分别等待 1、2、5 秒；仍未恢复则按用户设置的刷新间隔继续尝试。取得有效新窗口后清零重试状态，手动刷新可立即尝试。

Token 用量来自本机保留的官方 OpenAI Codex 会话日志，**不是账户的完整用量**。其他设备、临时会话和已删除的日志不会计入；同一天切换多个账号时，本地日志也可能混在一起。因此本机 Token 数可能与账户额度进度对不上。

绿色美元金额是按模型 API 牌价换算的**等价价值**，不是订阅费用或实际账单。价格来自 [OpenAI 官方 pricing.md](https://developers.openai.com/api/docs/pricing.md)，直接使用 Standard、Fast、Ultrafast 各档单价，不套用套餐额度消耗倍率。同一会话切换模型或档位时分别计价；单次请求输入总量（包含缓存输入）超过 272,000 tokens 时，使用该模型和档位的长上下文价格，整次请求的输入、缓存输入和输出均按该档计价。

缺少档位记录的历史用量仍按 Standard 估算；显式未支持的档位（如 Batch、Flex）按未知处理。设置日志不包含服务端逐请求的最终计费档位，金额仍是估算。任一窗口内有实际用量缺少模型、所需单价或计价依据时，该窗口金额显示 `--`，本期金额未知时“估值”也显示 `--`，不会把缺价部分按零算成完整总额。模型优先精确匹配，只允许标准日期后缀回退，不再把未知变体套用基础模型价。价格按当前公开牌价计算，不追溯历史价格；cache-write 暂未单独计价。“估值”会根据当前额度进度放大本机用量，误差可能更大。

用量缓存保存为 `usage-cache.json`，格式版本采用日期加当日序号（`YYMMDDNN`），当前为 `26100301`；只有缓存格式或日志解析规则变化、需要重建时才更新版本。首次运行新版会丢弃旧格式缓存并重读日志。

本期起点明确后，普通单文件会话会裁剪统计窗口之前的历史前缀，保留今日、本期所需事件和续读、去重、溢出判定的检查点；不会修改原始会话日志。同线程多文件和父子会话保留完整历史。窗口扩大或出现新副本、分叉时，会从原日志恢复相关历史后再聚合，因此这些刷新可能多读一些文件。恢复失败时，受影响的统计显示 `--` 并在后续刷新重试。日志会记录历史恢复文件数、裁剪事件数和余额观测数。

价格另存为 `openai-pricing-v1.json`，不使用旧 models.dev 缓存；首次无新缓存时，联网后约 30 秒获取价格，离线显示 `--`。之后每日自动刷新，托盘“立即刷新”也会更新价格并重算金额；抓取或解析失败保留上次成功价格，缺价日志包含模型、档位、上下文和价格项。离线重启可继续读取新价格缓存。

超额行中的美元来自账户 credits 余额变化，可能包含其他设备的消耗；它与旁边的本机超额 Token 数口径不同。

## 通知

托盘菜单的**通知**子菜单可分别开关两类提醒，默认开启：

- **额度重置**：额度窗口重置并恢复可用时提醒。
- **余额使用**：本周期首次观察到使用 credits 时提醒。

单击通知可展开面板。程序未运行、跟随 Codex 模式下已收起，或 Windows 抑制通知时，提醒可能不会出现；程序不会补发错过的提醒。

## 设置与排查

设置、缓存和日志位于 `%LOCALAPPDATA%\codex-quota\`。大部分设置通过托盘菜单修改，无须手动编辑 `config.json`。遇到持续显示 `--` 或刷新失败时，先确认 Codex Desktop 或 CLI 已登录，再点击**立即刷新**；Token 用量还需要本机会话日志。仍未恢复可查看 `codex-quota.log` 中所选后端的来源、路径和错误。如果只使用 CLI，可在 PowerShell 中运行 `codex --version` 检查安装。如果设置过 `CODEX_HOME`，工具会继承该目录的配置和登录态，还应检查其中是否有 `sessions`。

## 隐私

程序从本机会话日志中提取用量和额度相关元数据，不保存提示词、回复或工具输出。本地数据不会上传；程序自身的网络请求用于从 [OpenAI 官方价格文档](https://developers.openai.com/api/docs/pricing.md) 获取模型价格。读取账户额度时会临时启动 Desktop 或 CLI 提供的 Codex app-server，由该后端请求账户额度，完成后退出。
